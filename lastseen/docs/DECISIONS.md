# Decisions

Reasonable choices made without asking, newest last. Each line: decision, then why.

## M0

1. **Workspace lives in `lastseen/`, not the repo root.** The repo is a Unity project with a `Packages/` directory; on case-insensitive Windows/macOS filesystems `packages/shared` would collide with it. The brief's layout (`apps/`, `packages/`, `tools/`, `docs/`) is preserved one level down.
2. **Agent route is `/agents/tracker-agent/<deviceId>`.** The Agents SDK routes on the Durable Object *binding name*, so the binding is named `TrackerAgent` (same as the class) rather than `TRACKER`.
3. **Auth is a bearer token, also accepted as `?token=`.** Browsers cannot set headers on a WebSocket. Fail closed: no `DEVICE_TOKEN` configured means every request to `/agents/*` and `/api/*` (except `/api/health`) is rejected. Static assets are public (they contain no data); all data sits behind the agent.
4. **Clients never write agent state.** `validateStateChange` rejects any `setState` that does not originate on the server. Clients talk to the agent through typed messages (`ClientMessageSchema`).
5. **R2 is deferred.** R2 has to be enabled once in the Cloudflare dashboard (API error 10042); the binding is commented out in `wrangler.jsonc` and `env.FRAMES` is optional. Until it is enabled, small (160 px) thumbnails are kept in SQLite as data URLs, and keyframes are not persisted after OMNI has seen them. Enabling R2 is a two-line change (create the bucket, uncomment the binding).
6. **Keyframes go to R2 from the agent, before the Workflow starts, not inside it.** Workflow params and step outputs are capped (about 1 MiB), so six base64 JPEGs would not fit. The Workflow receives object keys. This reorders step (1) of the brief's pipeline; the pipeline is otherwise unchanged.
7. **Vectorize isolation uses the `namespace` query option (one per device), not a metadata filter.** No metadata index is needed and there is nothing to create up front. Index: `lastseen-objects`, 768 dims, cosine (Workers AI `@cf/baai/bge-base-en-v1.5`).
8. **OMNI adapter methods return `{ value, latencyMs, costCad }`** instead of the bare value in the brief's signatures, because the agent has to write latency and cost into every trace row.
9. **Strict JSON step protocol is the default even if native tool calling works.** One code path across proxies, and the same schema (`AgentStepSchema`) validates both real and mock output. One corrective retry on invalid JSON, then fail.
10. **Every OMNI call is streaming.** Qwen-Omni style endpoints are stream-only for audio output; using one code path for everything keeps it simple.
11. **The mock is the default whenever `MOCK_OMNI=1` *or* no `OMNI_API_KEY` is set.** Spending credit by accident is worse than silently mocking, and `/api/health` reports `mockOmni` so it is never invisible. `wrangler.jsonc` ships `MOCK_OMNI=1`; flip it to `0` after `wrangler secret put OMNI_API_KEY`.
12. **Mock test hook: base64 that decodes to JSON is a script.** A frame `{"mock":{"events":[...]}}` or audio `{"mockTranscript":"where are my keys"}` drives the mock deterministically, so the sim runs the real pipeline without images or speech. Anything else falls back to canned data.
13. **Cost is an estimate.** Pricing was not readable (yibuapi's pricing page is a client-rendered SPA). Defaults are deliberately high (2 / 8 CAD per M input / output tokens, 0.004 CAD flat when no usage block is returned) so the guard trips early, not late. Tunable with `OMNI_PRICE_IN_PER_M` / `OMNI_PRICE_OUT_PER_M`. The KV budget is read-modify-write and not atomic; it is a hard-ish cap, not an accountant.
14. **`vitest` v3, `eslint` v10, `typescript` 5.9.** Newer majors exist (TS 7, vitest 5) but the goal is a stable toolchain over a hackathon weekend. Tests are Node-only (no workerd pool); the Durable Object path is exercised by the sim over a real WebSocket against `wrangler dev`.
15. **Web apps are built into `apps/worker/public/`** (`/` from the wearable, `/dash/` from the dashboard) and served by Workers static assets. `run_worker_first` covers `/agents/*` and `/api/*` so assets can never shadow the backend.

## Patch 1: APK architecture (contract v2)

Adapted, not duplicated. Where the patch presumed code that did not exist yet (the repo was at M0), it was built directly in the v2 shape.

16. **The patch's "update ingest / update sim" became "build them".** At the start of the patch the repo had the M0 scaffold only: no tables, tools, agent loop, ingest pipeline, real dashboard or PWA, and no sim scenarios. The ledger, guards, ingest Workflow, agent loop with tools, dashboard, wearer TS layer and sim scenarios were written straight to the v2 contract rather than as a v1 that would then be patched.
17. **Contract v2 with v1 still accepted.** `hello` carries `contractVersion: 2`; a hello without it is a v1 client. v1 messages (`placement`, `frame`, `stop_speaking`, `pose{ts}`, `utterance{frameB64}`) are parsed and upgraded to their v2 equivalents on arrival (`packages/shared/src/compat.ts`), and v1 connections receive `reply` instead of `speak`. Where v1 lacks information the upgrade takes the permissive side: `stationary: true` (never drop for walking), the agent's current pose for `poseAtT`. `head_pose` is rejected by both contracts: it is local only.
18. **Every timestamp is epoch milliseconds**, documented in `schemas.ts`. The native payload schemas enforce a 2020-2100 range so uptime-millis, seconds or microseconds fail validation with a clear message (`pnpm validate:native`).
19. **`arrowAngle` changed shape; the old one was renamed, not deleted.** New: `arrowAngle(target, pose, headPose?, headOffsetDeg, nowMs)`. The bare-heading version is `arrowAngleFromHeading`, with its original tests. A head pose is fresh when 0 <= age < 300 ms; a timestamp from the future (clock skew) is treated as stale. `calibrateHeadOffset` returns the offset wrapped to (-180, 180].
20. **Detection protocol.** OMNI sees the detector boxes of the **final frame only** as `#i label score [x,y,w,h]` and answers `detection_index` (or null). Position uses the chosen detector box; else OMNI's own bbox; else no box: straight ahead (`phi = 0`) with confidence multiplied by 0.4 (0.85 for OMNI's box, 1.0 for a detector box). An out-of-range index counts as null. `detection_index` defaults to null when an older producer omits it.
21. **Cropping needs the Workers Images binding and only runs on the full-res still.** A Worker cannot decode JPEG, so `trim` on the Images binding is used. Local `wrangler dev` supports only a subset of transforms, so cropping is skipped there (traced as `crop_skipped`); the mock uses a passthrough cropper so the path is still exercised offline. 640 px keyframes are never cropped (below `CROP_MIN_PIXELS`, default 1 MP). The crop-describe call counts against the per-minute OMNI cap. A still above ~1.4M base64 chars is dropped with a trace, because a Durable Object SQLite row is limited to 2 MB; the native side must downscale stills to <= 1920 px.
22. **Guard semantics.** Order: `no_image`, `walking`, `duplicate`, `cooldown`, `rate_limit` (cheapest first, none calls OMNI). *Cooldown uses the candidate's own timestamp* (robust to network jitter, and lets the sim replay quickly on a virtual clock); the *OMNI rate limit uses the server wall clock* (it protects credit). A dropped candidate never extends the cooldown or enters the hash window. Hashes match when equal, or (same-length hex, up to 32 chars) within 4 bits. Guard state lives in SQLite so it survives Durable Object eviction. Explicit intent (`voice`, `manual`, `put_down`) skips only the walking guard, on the phone and the agent alike (`WALK_EXEMPT_TRIGGERS` is shared).
23. **The Workflow steps are idempotent RPCs into the agent** (`ingestExtract`, `ingestDescribeCrop`, `ingestReconcile`, `ingestNotify`), keyed by a candidate row, with status progression in SQLite. Frames stay in the agent (workflow params/outputs are size-limited). Transient OMNI failures throw so the Workflow retries; budget exhaustion is a clean skip. If `runWorkflow` throws, the same steps run inline.
24. **Privacy: only the thumbnail frame is kept.** After reconcile the agent deletes the other keyframes and any narration audio; a superseded thumbnail is deleted when an object is re-placed.
25. **Narration has its own key.** There is no speech recognition on the phone, so "putting my keys here" is captured with a dedicated hold-to-narrate key (`VOLUME_DOWN`); the audio goes with the frames as a `voice` candidate and OMNI fuses both. Query push-to-talk is `VOLUME_UP` / headset hook / play-pause; recenter is a long-press on next/previous. Screen taps and web volume-key code were not written (they do not work with the screen against the chest). Kept: a desktop keyboard map (browser fallback only) and a tap on the REC dot to toggle the debug overlay (not a PTT).
26. **Plugin fallback is per plugin, and the detector never falls back to the browser camera** inside the native shell (enforced in code and tested). Pose/keys may use WebView sensors/keyboard; head pose falls back to the chest heading. Every plugin has a side-effect-free `ping()` used for selection.
27. **`pose_correction` is applied in TS** (`PoseCorrector`), so native pose stays raw. The message and the handler exist, but **the agent does not send it yet**: zone anchors (original M5) are not built.
28. **`recenter`** is both an agent tool and a long-press gesture; it computes `headOffsetDeg = calibrateHeadOffset(pose, headPose)` locally and calls `zeroView()` natively.
29. **Semantic recall runs on Workers AI + Vectorize when `USE_VECTORIZE=1`, otherwise on an offline embedder + SQLite vectors** (local `wrangler dev` has no Vectorize). Vectorize upserts are eventually consistent, so `find_object` also matches on labels directly, and reconcile falls back to a same-label-within-1.5-m match while the index catches up.
30. **A bug found by the tests: label compatibility merged two different screwdrivers.** "Phillips screwdriver" and "flathead screwdriver" shared enough tokens to count as one object. `labelsCompatible` now requires the same head noun (or synonym) with no conflicting modifiers; "keys"/"car keys" and "mug"/"coffee cup" still merge.
31. **A bug found by the sim: "pick N evenly spaced frames" divided by zero for N = 1**, so `request_frame` and utterances (which ask for one frame) got no frame. Fixed in the mock, the browser detector, `CandidateFilter` and the OMNI client (N = 1 returns the newest frame), with regression tests.
32. **The sim runs the real phone-side code**: mock plugins -> `CandidateFilter` -> `Bridge` -> real WebSocket -> agent, on a virtual clock (no sleeps). It is a separate command (`pnpm sim:local`, needs `wrangler dev`) and not part of `pnpm check`; `pnpm check:all` runs both.
33. **`@capacitor/core` ^8.5.** The teammates' Android project (`@capacitor/android`, `@capacitor/cli`) must use the same major.

## Milestone A0: hello APK + hardware probes

34. **JDK 21, not the 17 the brief named.** Capacitor 8's Android library is compiled with `JavaVersion.VERSION_21` (read from `node_modules/@capacitor/android/capacitor/build.gradle`), so a JDK 17 build cannot work. The app module and Kotlin are set to Java/JVM 21 to match. Android tooling in Capacitor 8: AGP 8.13.0, Gradle 8.14.3, compileSdk/targetSdk 36, minSdk 24. *(Superseded in part: see 51-52.)*
35. **The toolchain was installed user-local because the machine had only Java 8 and no SDK.** Temurin 21 in `~/.jdks/temurin-21`, Android command-line tools + platform-tools + platform 36 + build-tools 36.0.0 in `%LOCALAPPDATA%\Android\Sdk`. No system PATH or global environment change; `scripts/android.mjs` finds them (or `JAVA_HOME`/`ANDROID_HOME`). Installing the SDK packages required accepting the Android SDK licenses, which was done to make the build possible: worth knowing.
36. **Kotlin was added to a Java-only template.** Kotlin Gradle plugin 2.2.20 (the version Capacitor 8 lists), `MainActivity` rewritten in Kotlin, local plugins registered before `super.onCreate` per Capacitor's custom-code docs. CameraX 1.6.2 (latest stable on Google Maven at the time). *(Superseded in part: see 51-52.)*
37. **Permissions: the milestone's nine plus three, one of them a real find.** `MODIFY_AUDIO_SETTINGS`: Capacitor's `BridgeWebChromeClient` requests `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS` together and grants the web `getUserMedia` request only if *all* are granted; undeclared, the audio request is denied even after the user allows the mic. `ACTIVITY_RECOGNITION` (step detector) and `HIGH_SAMPLING_RATE_SENSORS` (> 200 Hz on Android 12+) are needed by the sensor probe. So the WebView prompt handling is sufficient and no custom `WebChromeClient` was written. The **on-device** confirmation is still open (probe-results section 4). *(Superseded in part: see 51, 53.)*
38. **Orientation is not locked** (no `screenOrientation`); `configChanges` keeps the WebView alive on rotation. Screen stays on (`FLAG_KEEP_SCREEN_ON`); immersive mode is applied per route (`LastseenWindow.setImmersive`) for the HUD and display-probe routes only. *(Superseded in part: see 51, 55.)*
39. **Web layer restructured into hash routes** (`#/`, `#/settings`, `#/probe`, `#/display-probe`, `#/hud`). Hash routing works from `https://localhost` (bundled), a live Worker URL, and a plain browser. The previous wearer app is unchanged and now lives behind `#/hud` (a *Start HUD* button, since permissions need a user gesture); its old setup form and `loadConfig` were replaced by the settings store. The headless `?mode=mock&dev=1&autostart=1` smoke path still works through the route. *(Superseded in part: see 51, 57.)*
40. **Two web modes are decided at `cap sync` time** by `capacitor.config.ts` (`LASTSEEN_WEB_MODE`, `LASTSEEN_LIVE_URL`), driven by `pnpm android:sync|build [--live <url>]`. Live requires an `https://` URL (checked by the script and the config); cleartext is off in the manifest and in `server.cleartext`. `webContentsDebuggingEnabled` is on for debug builds; turn it off before any release build. *(Superseded in part: see 51, 56.)*
41. **Settings in Capacitor Preferences** (`WORKER_URL`, `DEVICE_ID`, `DEVICE_TOKEN`); optional defaults from build-time `VITE_*` env in an untracked `.env.local`, never from source. A token baked in at build time ends up in that APK's JavaScript: fine for a personal debug build, not for distribution. The URL is normalised to an `https://` origin; `http://` is refused except localhost. *(Superseded in part: see 51, 57.)*
42. **The WebSocket check has its own reconnect logic.** It measures round-trip time from the agent's own reply to `hello` (the still-deployed M0 Worker answers `reply`, current code answers `notice`; both count) and reconnects with 1 s, 2 s, 4 s ... capped at 30 s, +/-20 % jitter, reset on success. Written directly on `WebSocket` (not `AgentClient`/PartySocket) so the attempt number and countdown are visible on screen; unit-tested with a fake socket and fake timers. `apps/worker` and `packages/shared` were not modified (milestone constraint). *(Superseded in part: see 51, 57.)*
43. **Probe design.** One `Probe` plugin, one `CameraStreamer` (CameraX YUV analysis on the back camera) reused by the fps, JPEG, exclusivity and soak probes, one at a time. The plugin never throws: failures come back as `error` fields and the JS runner records them as failed steps, so one broken probe cannot stop the rest. The JPEG is produced **upright and 640 px wide**, which for a portrait frame is about 640 x 1138, larger than the 640 x 480 the earlier contract text implies: measure it, then decide whether keyframes should be 640 px on the long edge instead. FOV is reported for both sensor sides; in portrait the frame's horizontal FOV is the *short* side. *(Superseded in part: see 52, 54.)*
44. **Exclusivity is tested in both directions** (native first, then WebView first) and the native stream's frame counter is read between steps, so "the WebView was refused" and "the WebView got it and broke the native stream" are distinguishable.
45. **Keys are read through two paths** (`Activity.dispatchKeyEvent` and an active `MediaSession`), each event tagged with its `source`, because a Bluetooth clicker can arrive by either. Volume/media/headset keys are consumed while probing; BACK is never consumed. Timestamps are `System.currentTimeMillis()`.
46. **The foreground service is started from the visible app**, with the camera and microphone types, and reports any exception verbatim. It does not own the camera in A0: CameraX is bound to the Activity, so the camera stops when the app is backgrounded. Whether capture must survive screen-off is a decision this milestone informs (probe-results section 10).
47. **Automation.** `pnpm android:probe [--soak N]` grants the runtime permissions with `adb shell pm grant`, launches with intent extras (`probe_autorun`, `probe_soak_minutes`), waits for a `PROBE_DONE <path>` log line, and pulls `/sdcard/Android/data/dev.lastseen.wearable/files/probe/`. The 10-minute soak is opt-in. *(Superseded in part: see 56.)*
48. **No device was attached, so no probe has produced data.** Everything verifiable without hardware was verified (APK manifest via `aapt2`, the bundled/live configs, every route in headless Chrome, the WebSocket RTT to the deployed Worker from a desktop browser: 24-29 ms). `docs/probe-results.md` marks every device measurement `TODO` rather than filling anything in.
49. **The deployed Worker was not redeployed.** Live mode against `https://lastseen.m55chan.workers.dev` would load the old M0 page; to iterate live, deploy the current web build (`pnpm deploy`) or tunnel the Vite dev server over https.
50. **one-xr (glasses IMU) is cloned to `tools/one-xr`, git-ignored, not integrated.** MIT licensed (see `docs/glasses-imu-probe.md`).

## Milestone A0, revised: Capacitor removed, pipeline kept

51. **Capacitor is out of the A0 deliverable (owner decision: "we do not need Capacitor, the frontend and everything will be sorted out; all I need is the pipeline").** Deleted: `apps/wearable/android` (the Capacitor project), `capacitor.config.ts`, the Home / Settings / Probe / Display-probe web routes with their router, `probeRunner`, `wsCheck`, `webMedia` and `native/probeApi.ts`, and the `@capacitor/android`, `@capacitor/cli`, `@capacitor/preferences` dependencies. All of it was uncommitted, so a tarball backup was taken outside the repo before deleting. **Deliberately not touched:** `@capacitor/core` and `native/capacitor.ts` (the contract v2 bindings to the teammates' `Lastseen*` plugins), `NATIVE_CONTRACT.md` and `ARCHITECTURE.md` (both still say "Capacitor APK"), `packages/shared`, `apps/worker`. Those describe the product frontend's native bridge, which is the frontend owner's decision; until it is made they degrade as designed (`ping()` fails, `select.ts` falls back to mock/web).
52. **The probes are a plain Android app: `apps/probe`, package `dev.lastseen.probe`.** Kotlin + Gradle, `ProbeActivity` (buttons and a log) and `DisplayProbeActivity`. The CameraX streamer and the sensor, camera, keys, soak and foreground-service probes were carried over unchanged apart from swapping Capacitor's `JSObject`/`JSArray` for a small chainable `org.json` wrapper that also stores NaN/Infinity as null instead of throwing. The id differs from any product app so both can be installed side by side. JDK 17+ is enough now (21 was a Capacitor 8 requirement); the app compiles to Java/Kotlin 17.
53. **One WebView remains, inside the exclusivity probe only.** Whether the WebView can open the camera while native CameraX streams (and the reverse) can only be answered against a real WebView, and the future frontend may be one, so `WebProbe` loads a tiny page from `https://localhost/` into a 1x1 WebView and calls `getUserMedia`. Its own `WebChromeClient.onPermissionRequest` grants a request only when the Android runtime permission is already granted and records what was asked and decided (this is task 3's "implement the WebChromeClient permission handling", done natively). Results come back through `addJavascriptInterface`. Same JSON shape as before (`nativeFirst`, `webFirst`, `summary`). `MODIFY_AUDIO_SETTINGS` stays declared, but whether a plain WebView needs it is unverified.
54. **Orchestration moved from TypeScript to Kotlin (`ProbeRunner`).** Same steps, same JSON schema 1: device, permissions, display, sensors, camera, exclusivity, foregroundService, soak, save. The report file is rewritten after every step so a crash leaves partial data, a failing step is recorded and the run continues, and `PROBE_DONE <path>` is logged at the end. The JS viewport numbers are gone; `display.native` gained the activity window in px and dp and its orientation.
55. **The display probe is a native Canvas view.** Same content as the web version: black, grid, frame, cross-hair, arrow (one turn per 30 s), TL/TR/BL/BR markers, four swatches, font ladder 24/32/48/64. The ladder is in **dp**, which equals CSS px in a WebView, so the sizes match what a WebView HUD would render; the brief said "px". It draws under the display cut-out, is immersive, and is not orientation-locked.
56. **The pipeline is `scripts/android.mjs` + `scripts/probe-report.ts`.** `pnpm android:doctor|build|test|install|run|logcat|probe|report`. `android:sync` and `--live` are gone (there is no web layer to sync). `android:probe` grants permissions, launches with autorun, waits for `PROBE_DONE`, pulls the device folder, then writes `summary.md` and patches the `AUTO` blocks in `docs/probe-results.md`; anything the app did not measure stays `TODO`. Human fields sit outside the `AUTO` blocks so a re-run never overwrites them. The key probe also writes `keys-<epoch>.jsonl` so Bluetooth-clicker results survive as data.
57. **Dropped with the web layer and not re-implemented natively:** the WebSocket RTT check with backoff (task 5) and the Settings screen storing `WORKER_URL` / `DEVICE_TOKEN` (task 4). Both are frontend concerns. So the HUD still boots, `settingsStore.ts` now resolves URL query params (`?host=&device=&token=`) over build-time `VITE_*` defaults (nothing is stored on the device, no secret in source), and `routes/hud.ts` is the page at `/`; without `host` it uses the page's own origin, which is the Worker when the Worker serves it. `ui.ts` helpers that only the deleted routes used were removed. The earlier 24-29 ms desktop RTT to the deployed Worker is the only RTT number; the phone's is unmeasured.
58. **Verification is still off-device** (as in 48): Gradle build, 8 JVM unit tests, `aapt2` checks of the merged manifest, and the report generator against a report shaped like the Kotlin output. The Kotlin runtime behaviour (CameraX, WebView, sensors, service, keys) has not executed on any device, and the first real report may reveal a key mismatch in the generator.
